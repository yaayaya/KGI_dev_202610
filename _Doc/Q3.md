# Q3：借券利息結算與監控

依批次計算借券單日利息並監控結算結果，頁面入口為 `/interest`。操作與監控皆使用 Vue，與其他功能共用單一 `KGI`。

## 操作

1. 依 [README 啟用 Q3](../README.md#啟用-q3)，開啟「借券利息結算」。
2. 選取批次，查看預計總額、狀態、進度、起訖時間與結算結果。
3. 對待處理批次按「啟動結算」，在確認視窗核對批次編號與預計總額後送出；取消不會啟動，確認期間狀態或金額已改變時不可送出。
4. 受理後由背景工作者執行，頁面每五秒更新。成功顯示 100%、實算總額與明細；失敗顯示紅色告警及錯誤訊息。

後端每處理 200 筆發布一次進度，明細處理完成時最多 95%，成功提交才到 100%。若整批在兩次輪詢之間完成，畫面可能從 0% 直接跳到 100%；目前顯示最新進度，不保留步驟歷程。

輪詢失敗保留舊資料並提示更新異常；啟動請求結果不明時先查狀態，不自動重送。離開頁面不會取消已受理的結算，重新開啟可接續監控。

## 計息與校驗

原題未提供本金、利率及計息基礎，本版採合成來源與下列示範公式：

```text
單日利息 = 本金 × 年利率 ÷ 365
```

- 本金為 `DECIMAL(18,4)` 正值；年利率為 `DECIMAL(9,8)` 正值，例如 3% 保存為 `0.03000000`。
- 使用 C# `decimal`，每筆以 `MidpointRounding.AwayFromZero` 四捨五入至四位小數，再寫入及加總。
- 預計總額 `Expected_Amt` 獨立保存，不以實算結果覆寫。依原題的明確門檻，絕對差異 **大於 0.0001** 時失敗，等於 `0.0001` 可成功。
- 明細寫入、SQL 總額校驗與成功狀態在同一交易內；失敗回滾全部明細，再獨立保存失敗狀態與錯誤訊息。

來源為每批固定的本金與利率快照，與 Q2 擔保品分開。本版未提供批次或來源編輯、凌晨排程、失敗重試及正式計息來源串接。

## 批次狀態

| 狀態 | 意義 | 可否啟動 |
| --- | --- | --- |
| 0 | 待處理 | 可以 |
| 1 | 已受理／處理中 | 不可以 |
| 2 | 結算成功 | 不可以 |
| 9 | 失敗或程序中斷 | 不可以，需人工處理 |

同批並行啟動僅受理一次。重啟後，尚未開始的已受理批次可續行；已開始且失去工作者鎖的批次會標記失敗，不自動重跑。失敗保留最後發布的進度，不顯示 100%。

## API

| 方法與路徑 | 用途 | 成功狀態 |
| --- | --- | --- |
| `GET /api/interest/batches` | 批次列表與進度 | 200 |
| `GET /api/interest/batches/{id}` | 單批快照與已提交明細 | 200 |
| `POST /api/interest/batches/{id}/settlement` | 受理結算，不需 request body | 202 |

單批回應包含 `batch`、`calculatedAmt` 與 `details`；未成功時實算總額為 null、明細為空。金額為四位小數字串，時間為 UTC ISO 8601 字串或 null，畫面轉為台北時間顯示。

啟動成功附 `Location` 查詢網址；無效編號回傳 `400`、查無批次 `404`、非待處理批次 `409`、未啟用功能或缺少必要資料表 `503`。錯誤使用 ProblemDetails。

## 設計架構

- 前端：[interest 功能目錄](../Kgi.Web/src/features/interest/)，由 `useInterestMonitor` 管理輪詢與啟動狀態，Vue 元件呈現批次、進度及明細。
- 後端：[Interest 功能目錄](../Kgi.Api/Features/Interest/)，採 `Controller → InterestService → InterestDao → KGI`；Service 負責計息與流程，Dao 使用 Dapper 管理 SQL、交易及批次鎖，背景工作者每兩秒檢查待執行批次。
- 資料：`Interest_Batch` 保存狀態與預計總額，`Interest_Source` 保存來源快照，`Interest_Detail` 保存成功明細；進度獨立發布，監控不讀取未提交明細。
- 測試：與 API 共用 `ConnectionStrings:Kgi`，只建立及清理自己的批次，以指定批次執行結算，不自動重建資料庫或執行其他既有批次。
